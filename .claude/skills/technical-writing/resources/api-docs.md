# API Docs

API docs describe what is RIGHT NOW. Occassionally they may describe why other solutions than the current one was considered but discarded but those should be rare occassions where that description of previous states or decisions help illuminate or illustrate somethign about way things are RIGH NOW in the application code base or functionality. API docs are primarily explanatory type documents.

## Intended Audience
The intended audience of API docs are other developers. In large and/or complex codebases its especially important to have good, accurate API docs that help a developer.

## Tasks of API Docs
- to help a developer go from no understanding of the application or project to a high level model or conceptual model of the project or application
- to help a developer go from a concept they already understand to more detailed understanding of the concept by pointing to other docs and/or code
- to help a developer go from a specific fuction, class, or piece of code back to the larger concept the fucntion, class, package, or code is supporting
- to help a developer discover the application or project capabilities and/or explore existing implementation

If the documentation written does not support the developer in one of these tasks then it is probably not an API doc.

## Examples of documents that are NOT API docs
- Code comments
- PR descriptions
- README
- How tos and tutorials
- ADRs
