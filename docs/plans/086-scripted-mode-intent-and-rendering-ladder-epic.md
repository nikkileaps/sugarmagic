## Why now

Scripted mode is not actually zero-LLM: every NPC-spoken authored line is adapted per learner at RUNTIME via a gateway call (sugar-lang-scripted-middleware.ts:151). That means per-player cost and latency on every scripted NPC line, output nobody can review before players see it (and silent fallback to authored English on failure, so behavior is not even consistent), and a broken promise -- the Strategy 001/002 contract says authored narrative is PLAYABLE with zero runtime LLM. Market evidence says trust in generated target-language accuracy is the number-one review killer for LLM-era titles; a finite, bake-time-verified, natively-auditable corpus is the direct answer, and pure runtime generation can never provide it.

The strategy's model: a scripted line's ground truth is its INTENT (must-convey facts, dramatic beat, voice), with the authored English as the canonical expression and fidelity anchor. One rendering principle, two intent sources (authored line / plan-stage goal); the TEACHER decides, the model RENDERS, the verifiers CHECK.

## Non-goals

- No general-purpose MT API: the job is level-constrained voice-preserving rendering, not faithful translation; everything routes through the existing gateway.
- No changes to agent-mode rendering (epic D territory) beyond adopting shared verifier functions.
- No live-render TRIGGER logic: "is this line the moment" is epic E's call; this epic ships the callable path with the trigger stubbed to off.
- Authoring UI is SCOPED, not open-ended: the per-node variant popover in the Dialogue workspace (see 086.1/086.3) and the exception-review report. No standalone form-editor workspace, no bulk-edit grid.
- No bark system.

## Design principles

- The rendering ladder, floors first: deterministic weave (zero LLM) -> baked variants (bake-time LLM, triple-verified, shipped as assets) -> directed live render (runtime LLM, same verification, baked fallback). Each rung is independently shippable and the lower rung is always the fallback.
- Authored English is the fidelity anchor: every rendering verifies against it (must-convey facts present, meaning preserved); the exception-review report is readable WITHOUT speaking the target language (back-glosses, flags).
- Bias toward deletion: the unconditional runtime scripted call DIES in this epic; nothing keeps it alive behind a flag.
- Deterministic verifiers (envelope, ratio, voice retention) are pure functions on the classifier facade (the 083 contract: callable outside the middleware), composed at bake and at runtime identically. Must-convey FIDELITY is the one non-deterministic gate: it is an LLM-assisted check at BAKE ONLY (the extract-chunks precedent: gateway + schema validation + content-hash cache). At runtime (086.5) fidelity gets a deterministic floor instead: required lemmas/chunks/quest-essential facts present in the rendered text -- no LLM verifier ever runs on the turn path.
- Turn budget: scripted common path = ZERO runtime model calls (weave or baked); directed live render is opportunity-priced, cached by (line, band, posture, teachables).
- Bake verification runs against synthesized per-band learner profiles (empty lemmaCards, estimatedCefrBand = band) since EnvelopeClassifier.check takes a LearnerProfile, not a band.
- MIXED-TEXT ENVELOPE PREDICATE (round-2 blocker fix): applyEnvelopeRule's `withinEnvelope` carries an UNCONDITIONAL coverageRatio >= 0.95 floor (envelope-rule.ts), and support-language (English-frame) tokens fail target lemmatization into unknownTokens (coverage.ts) -- so every mixed-language weave line and every 80/20 variant fails `withinEnvelope` regardless of exemptions (Plan 083 line 25 documents this coverage collapse as correct AGENT-mode behavior). Strategy 002's "coverage-compliant by construction" is a pedagogy claim, not a classifier fact. This epic therefore ships a NEW shared pure function beside applyEnvelopeRule -- the mixed-text envelope predicate (round-3 correction: NO coverage-floor leg; over target-resolved tokens the floor is degenerate -- exempt-counts-as-covered makes it vacuous, exempt-counts-against structurally fails any line that introduces, and introduction is the point):
  (1) non-exempt violations <= ENVELOPE_OUT_OF_ENVELOPE_ALLOWANCE (the agent-mode allowance of 2, deliberately kept: support-language homographs lemmatize against the target atlas -- e.g. English "mole" is a B1 es lemma -- and zero allowance would hard-fail whole lines on one homograph; C2-at-B1 is still caught by leg 2 regardless);
  (2) zero non-exempt ceiling exceedances.
The one thing the old floor caught in mixed text -- atlas-unresolvable target words landing in unknownTokens -- is backstopped by the language-ratio gate running beside this predicate at bake and runtime, plus the bake fidelity gate. New-word density is bounded by the prescription budget (distinct exempt introduce lemmas <= budget.newItemsAllowed), not a token ratio. Built in 086.2, reused verbatim at 086.3 bake and 086.5 runtime. applyEnvelopeRule itself is untouched (agent mode keeps its floor). CALL-SITE PIN: predicate call sites must build coverage with the INVENTORY chunk matcher (EnvelopeClassifier resolves its matcher from sceneLexicon.chunks only; woven/baked chunks come from the function inventory -- the exact trap 085 already fixed in the observe middleware); the sceneLexicon chunks pick accepts inventory chunks.

## Stories (EXECUTION ORDER)

### 086.1 Line-intent model + compile artifact

The intent contract per authored line: must-convey facts (including questEssentialLemmas-linked info), beat, voice note, with the authored English text as anchor. Compile pass derives a first-cut intent artifact from existing authored content (LLM-assisted at bake where fields are not authored -- the extract-chunks precedent: gateway + Ajv validation + content-hash cache + fail-soft telemetry); hand-authored fields win. NOTE: extract-chunks has NO flag-for-review mechanism -- failures yield empty results + telemetry; the review-flag surface is NEW scope, built in this story (persisted on the artifact) and surfaced in 086.3's report.

CROSS-PACKAGE SCOPE (not just a sugarlang compile pass): authored intent fields ride DialogueNodeDefinition in the domain package. normalizeDialogueNodeDefinition (domain/dialogue-definition/index.ts) rebuilds nodes from a fixed literal and silently strips unknown fields, and Studio round-trips through it -- so this story touches (a) the domain type + normalize function, (b) Studio dialogue-editor persistence of the new fields, (c) the sugarlang compile pass. Line identity for keying already exists: turnId = `${dialogueDefinitionId}:${node.nodeId}` (runtime-core conversation). CACHE PRECEDENT (round-2 correction): the right model for LLM-derived artifacts is SugarlangChunkCache -- keyed `lang:extractorPromptVersion:contentHash` (chunk-cache.ts) precisely so PROMPT changes invalidate alongside content changes. The intent artifact cache follows that shape (own prompt-version constant); scene contentHash covers dialogue node text (scene-traversal), so content invalidation is free. SugarlangCompileCache (profile:sceneId:contentHash, typed to CompiledSceneLexicon) is the wrong precedent for this layer -- do not force intent artifacts into it, and do not invent a third scheme.

AUTHORING SURFACE (post-lock amendment 2026-07-27, nikki): the intent fields are edited in the Dialogue workspace via a "Variants" button in the node inspector that opens a popover. DECOUPLING PIN: the button/popover ship as a sugarlang shell contribution mounted through the plugin-owned inspector-section seam (the established pattern: design workspace index.tsx accepts plugin-owned inspector renderers; layout workspace does the same for the region inspector). If the dialogue inspector does not expose the seam yet, adding it follows that pattern and lives in the workspaces package with zero sugarlang knowledge. NO sugarlang import in dialogue workspace code; sugarlang not installed = no button. Left side: target-language list (the languages with data in the project -- es, it today); selecting one scopes the right side. Right side: the intent fields (must-convey facts, beat, voice note -- language-agnostic, shown once) and, below them, one text field per deep-end band (B1+) holding that language's variant (086.3 populates these; A1/A2 have no fields -- the weave is deterministic, nothing to author). This story ships the popover with the intent fields; 086.3 adds the band fields and the generate button.

- Exit: intent artifacts compile for a fixture region; authored-field override pins (round-trip through normalize + Studio save proves fields survive); popover opens from the node inspector and edits/persists intent fields; cache round-trip + invalidation tests; docs/api page for the intent format.

### 086.2 Deterministic weave (anchored/supported postures; the zero-LLM floor)

Authored English verbatim as the frame; runtime substitution of the live prescription (introduce/reinforce lemmas AND chunks, glossing per strategy). SCOPE CORRECTION (epic-review round 1): the morphology data is a one-way surface-to-lemma index (every es entry is `{lemmaId, partsOfSpeech}` -- no inflection features, no lemma-to-form direction), so "correct surface forms from atlas morphology" is NOT achievable. The weave substitutes CITATION FORMS + chunk surface forms from the function inventory, following the existing auto-simplify resolveReplacement precedent (lemma citation form + gloss marker). This is defensible for the diglot-weave on-ramp (L2 words in L1 frames, Strategy 002 item 6); inflected-form substitution needs a feature-tagged inverse morphology index -- a real data-engineering story, DEFERRED with trigger below. Full per-learner adaptivity with zero LLM and zero translation risk. This replaces the runtime LLM call for anchored/supported postures immediately.

SUBSTITUTION MECHANICS (round-2 pin): substituted target forms go into the text BARE (the resolveReplacement lemma-branch precedent returns a bare lemmaId; its `*gloss*` wrap is only the gloss-FALLBACK branch). Never wrap introduced forms in `*...*` -- tokenize strips all asterisk spans as gesture tags (083.3), which would erase the introduced words from coverage, ratio, encounter counting, AND false-positive the voice-retention check. Glossing is delivered via the existing dialogueHighlight annotation path (glosses map in the observe middleware), not inline markers. The teacher middleware's scripted branch currently hardcodes glossingStrategy "none" -- this story emits a real per-posture value there (small named scope).

This story also builds the MIXED-TEXT ENVELOPE PREDICATE (see design principles) as a shared pure function beside applyEnvelopeRule; 086.3 and 086.5 reuse it verbatim.

Weave-introduced lemmas/chunks feed the 085 observation loop (HARD DEP: 085 merged -- see Related): the observe middleware matches chunks from the function inventory on turn text, so encounter counting is automatic; first-teach (085.5 teach records) fires naturally when the weave introduces a new chunk. Pin this with a test, not new plumbing.

- Exit: weave unit tests (citation-form + chunk-surface substitution BARE in text, chunk insertion, glossing via dialogueHighlight respected, mixed-text envelope predicate passes on woven output WITH the prescription passed); integration: an anchored-posture scripted line plays woven with zero sugarlang generate calls (fetch guard matching /generate exactly -- not by prefix; fixture pins moderation off); a woven first-teach chunk produces a teach record.

### 086.3 Bake-time variant generation + triple verification + exception report

Per-line variants for deep-end BANDS (B1 and up) generated at Studio bake, content-hash cached, shipped as assets. BAKE TRIGGER (post-lock amendment 2026-07-27, nikki): the bake runs AUTOMATICALLY on dialogue create/update/delete when changes save, riding the existing SugarlangAuthoringCompileScheduler (debounced, per-scene -- the 085 chunk-extraction precedent, with its own debounce window); the content-hash cache makes it incremental, so only changed lines regenerate. Authoring never requires leaving the Dialogue workspace. The sugarlang workspace keeps a rebake-all button as the just-in-case full pass. Variants are keyed by BAND; posture is derived from band at selection time (086.4). POSTURE CORRECTION (epic-review round 1): the scripted posture ladder is anchored (A1) / supported (A2) / target-dominant (B1+) -- `target-only` NEVER occurs in scripted mode (sugar-lang-teacher-middleware.ts posture mapping), so no target-only variants are baked; if a future epic extends the scripted ladder, the band-keyed variants absorb it without rebake.

Verification at bake, all four gates: the MIXED-TEXT ENVELOPE PREDICATE (built in 086.2, not applyEnvelopeRule -- see design principles) + ratio (083.1 pure function), both against a synthesized per-band learner profile; voice retention (computeVoiceRetentionScore -- SHIPPED in 083, composes from day one; re-export from the classifier facade first, bake must not import the verify-middleware module); and must-convey fidelity (LLM-assisted at bake per the design principle above; this is the one LLM gate and it runs at bake only). Studio surfaces the exception-review report: flagged lines (086.1's review flags + verify failures), English back-glosses, fidelity scores -- reviewable by a non-speaker, auditable by a native speaker later. The report is a Studio shell contribution panel (the established ui/shell/contributions.ts pattern).

SHIP CHANNEL (round-2 scope true-up): publishSugarlangArtifacts EXISTS but has ZERO production callers -- it is a future integration point, not a wired pipeline; the runtime today gets lexicons via the compile cache / lazy compile. Wiring Studio bake -> deployed asset -> runtime load for variants is REAL SCOPE owned here (bake/persist side) and in 086.4 (runtime load side). Use publishSugarlangArtifacts as the packaging shape, but budget for wiring both ends.

PER-LINE AUTHORING (post-lock amendment 2026-07-27, nikki): the 086.1 popover gains its band fields and a generate button at the top. Clicking it runs THIS story's generation + all four gates for the selected language, this line only, and populates the band fields with the results (verify flags shown inline; flagged text is visible but marked, same rule as the report: flagged never ships). Hand-EDITED variant text pins over generated (same hand-authored-wins rule as intent fields) and still runs through the deterministic gates on save -- a failing hand-authored variant is flagged in the popover and the report, not silently shipped. The bulk bake path is unchanged and uses the same cache, so a line generated from the popover is a cache hit at next full bake. MODEL: generation rides the new bake `purpose` (owned by this story); pointing it at an expensive model (e.g. Fable) is a deploy-time env decision, per the server-side model-selection rule -- bake-time cost is one-shot and cached, so spend freely there.

- Exit: bake produces variants for a fixture region with verification verdicts persisted; a deliberately-broken variant lands in the report, not in the shipped assets; cache-hit second bake generates nothing; report visible in Studio.

### 086.5 Directed live render path (the ceiling, callable but dormant)

The opportunity-triggered re-render: intent + teachable + scene rendered live, then verified at runtime with the DETERMINISTIC gates only (the mixed-text envelope predicate + ratio + voice retention -- the same pure functions as bake) plus the deterministic fidelity floor (required lemmas/chunks/quest-essential facts present in the rendered text); NO LLM verifier on the turn path (see design principles -- the LLM fidelity judge is bake-only). On any verify failure the baked variant plays; cached by (line, band, posture, teachables), in-memory (derivable state -- no SaveParticipant; if persistence is ever wanted, follow the IDB-store pattern, not a save slice). The trigger input is a stub (off) until epic E wires it -- this story proves the path with a forced trigger in tests only.

- Exit: forced-trigger integration renders live, verifies, caches (second call = cache hit), and falls back to baked on injected verify failure; with the trigger off, behavior is byte-identical to 086.4.

## Verification recipe (nikki)

1. `pnpm test` green, `pnpm lint` clean.
2. Zero-LLM probe: kill the local gateway entirely; play a scripted quest at A1 and at B2 -- every line plays (woven at A1, baked at B2), no hangs, no fallback English at B2 unless the variant is missing (then weave). Moderation is fail-open so a dead gateway does not block input.
3. Trust probe: Studio bake on a fixture region -> open the exception report -- flagged lines readable with back-glosses; nothing flagged shipped.
4. Cost probe: second bake of an unchanged region generates nothing (bake log/telemetry).
5. Latency: scripted lines now display instantly (no per-line gateway round-trip).
